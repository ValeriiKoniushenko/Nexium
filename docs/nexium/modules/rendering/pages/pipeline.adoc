= Rendering Pipeline

== Frame order and destinations

The loop in `NxRuntime/Runtime.cpp` uses the previous frame's measured delta; the first delta is zero.

Before the loop starts, Runtime sets the clear color and the global GL state once:
`GL_BLEND`, `GL_CULL_FACE`, and `GL_STENCIL_TEST` enabled, `GL_DEPTH_TEST` *disabled*.
Every clear uses colour + depth + stencil bits.

[cols="1,3,3",options="header"]
|===
|Step |GameOnly |Editor
|1 |Poll events, route input, tick the current scene, set the GL viewport to the window's framebuffer size. |Poll events, route input; tick the current scene only when the viewport is focused.
|2 |Clear the window; update integration keyboard actions if attached. |Clear the window; update editor windows/input and submit ImGui drawing.
|3 |Use the active camera to draw the current scene into the window. |Process picking, bind and clear the viewport target, then draw the current scene.
|4 |Call GameInstance's tick hook after drawing. |Call that hook while the viewport target is still bound, then bind framebuffer 0.
|5 |Apply queued scene changes. |Same.
|6 |Swap buffers and record elapsed time. |Same.
|===

Steps 3–4 require an active camera, which is the current scene's. Scene tick and drawing are
therefore separate gates. When the editor's scene loses its camera, Runtime clears the viewport
target once so it does not keep showing the last frame. A scene switch queued during the frame
takes effect at step 5, so the next frame ticks and draws the new scene.
The editor submits ImGui before refreshing the viewport texture, so the displayed image can contain
the previous scene render. There is no independent simulation/render clock.

== Scene draw order

Runtime passes the `skybox` and `grid` programs into `Scene::directDraw(skyboxShader, gridShader)`.
The method returns immediately when the scene is not active in a World or that World has no
camera, and otherwise:

. Draws a hard-coded `"Hello world"` string through the scene's own `NX::Face`, generating the
  glyphs on the first draw. This is a development leftover in the normal draw path, not a feature.
. Draws the grid in Editor mode.
. Handles enabled root mesh bundles when 3D is compiled in, collecting those marked post-draw.
. Calls `draw()` on the root objects.
. Draws the collected mesh bundles, then attempts a skybox for a perspective camera.

This is an explicit sequence, not a depth-sorted transparent pass. The general root loop also
calls mesh roots; do not infer a once-per-object guarantee from the post-draw flag.
The skybox is drawn only for a perspective camera and only when a `skybox` program exists;
`AssetsManager::getSkybox()` still asserts "Not implemented", so skybox assets cannot be loaded. Ordinary `SceneObject::draw()` checks its enabled flag;
component tick traversal does not automatically imply child rendering.

== Example: one atlas-backed rectangle

=== Geometry and camera

`Rectangle::onDraw()` reuses a shared four-vertex quad and six indices.
The `2d_rect` vertex shader expects a position at attribute location 0.
The model matrix transforms the quad, while `uProjAndView` applies the camera's view/projection.

=== Atlas and frame coordinates

Atlas lookup returns the packed image's offset and size in normalized coordinates.
The rectangle's frame UVs select a region within that image:

* Final offset = atlas offset + atlas size × frame offset.
* Final size = atlas size × frame size.

For an atlas image at `(0.25, 0.5)` with size `(0.5, 0.25)`, selecting its right half
(frame offset `(0.5, 0)`, size `(0.5, 1)`) sends offset `(0.5, 0.5)` and size `(0.25, 0.25)`.
The CPU uploads those values immediately before drawing:

----
include::example$rectangle.cpp[tag=rectangle_draw_uniforms,indent=0]

=== Alpha handling

With blending enabled, the fragment shader discards samples below alpha 0.1 and the draw uses
source-alpha blending. Disabling blending forces fragment alpha to 1 and uses replacement blending.
Runtime disables depth testing for the whole run, so draw order alone decides what covers what:
2D roots paint in scene-object order, and the alpha discard is what keeps sprite edges clean.
Any depth-dependent content has to enable and manage `GL_DEPTH_TEST` itself.

See xref:materials/shader-system.adoc[Shader System] for the matching GLSL and binding sequence,
and xref:text.adoc[Text Rendering] for the glyph path.
