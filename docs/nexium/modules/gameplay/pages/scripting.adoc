= Gameplay Hooks

Gameplay behavior currently runs in compiled C++; there is no embedded gameplay scripting runtime.
Component hooks include `onInitialize()` and `onTick(float)`.
Call the base tick hook when a derived component must also tick its children.

Game-specific setup lives in the `GameInstance` hooks for shaders, resources, cache loading,
and saving. `GameInstance::onTick()` runs after drawing and requires an active camera.
See xref:engine_architecture:lifecycle.adoc[Application Lifecycle] before choosing that hook
for camera-independent simulation.

To change scenes from gameplay code, use `GetSceneManager()->requestCurrentScene()` and the other
`request*` calls; the immediate calls are refused during a tick. See xref:scenes.adoc[Scenes].

The hooks are declared in `NxWorld/Framework/GameInstance.h`.
`game-example/TemplateGameInstance` currently inherits their default behavior without overrides,
so all example behavior lives in components instead.

== The worked example

`game-example/Player` is the pattern to copy for gameplay behavior. It derives from
`RectangleAnimated`, calls the base `onTick()` first, and then:

* polls `Platform::Keyboard::IsKeyPressed()` for W/A/S/D and the arrow keys, normalizes the
  result for diagonals, and applies it through `moveRight()`/`moveUp()`;
* looks up its `FrameByFrameAnimator` child with `findFirstChildOf<T>()` and switches it to the
  animation matching the movement direction.

The keys are hard-wired because `Player` predates the current `InputController`. New gameplay
code should add a child `InputController` with named actions and read them in `onTick()`, the way
the spectators do — see xref:engine_architecture:input-system.adoc[Input System].
