= Gameplay Components

== Choose behavior or a drawable object

Use `BaseComponent` for behavior attached to another object, such as an animator.
Use `SceneObject` when the object needs transforms, scene persistence, and a draw hook.
A component tree expresses ownership and tick propagation; it does not automatically make every child drawable.
`Actor` currently adds little beyond SceneObject, so derive from it only where that existing hierarchy is useful.

== Register and persist a component

A concrete component uses `ECS_DECL` in its declaration and `ECS_IMPL` in its implementation.
Use `CLASS()` and `FIELD()` for JRM-reflected types/fields, and include the generated header as existing types do.
The normal build regenerates metadata. The xref:engine_architecture:ecs-overview.adoc[Component System]
lists constructor/template macro variants.

Factory registration and field serialization solve different problems: the factory chooses the C++ type,
then the deserializer restores that type's reflected state.
Renaming a serialized component type needs a content migration; renaming a display label does not change its type.
Unreflected runtime state, such as subscriptions or borrowed resource pointers, needs explicit setup after reconstruction.

== Build a tree without accidental copies

=== Creating versus attaching

`addChildComponent<T>()` creates and owns a new child, assigns its parent, and initializes it.
`attachChild()` instead clones the supplied tree. It does not move the original into this parent.

Keep a strong `Core::IntrusivePtr` if a component must survive removal from its parent.
The raw pointer returned by an add operation is borrowed. Detach/removal clears its parent link,
but selection or another strong reference may keep the object alive.

== Initialization and ticking

=== Initialization can happen during assembly

Adding a child initializes an uninitialized parent first, then the new child, before returning.
An `onInitialize()` hook must not assume siblings that will be added later already exist.
Repeated `initialize()` calls do nothing until invalidation; invalidating a parent alone does not invalidate its children.

== Example: animating a rectangle

A `FrameByFrameAnimator` must have a `RectangleAnimated` parent for frame application.
`startAnimation(name)` restarts the selected animation and applies its first frame immediately.
Each subsequent tick advances time, chooses the frame's texture or animation default,
then sets the parent's atlas, texture, and UV region.

The parent draw converts those frame UVs into atlas coordinates; the xref:rendering:pipeline.adoc[Rendering Pipeline]
shows the calculation. Animation selection changes which pixels are sampled, not the quad's vertex data.

== What a scene actually saves

Inline scene roots save their reflected component trees. Template-backed roots save an asset reference
and supported instance values, not arbitrary changes to every child field.
Cloning a tree copies descendants but does not prove that GPU resources/subscriptions were safely copied.
See xref:scenes.adoc[Scene persistence] before relying on component edits to survive reload.
