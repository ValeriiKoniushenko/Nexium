= Application Lifecycle

The application entry point is `game-example/main.cpp`.
The frame loop lives in `sources/NxRuntime/Runtime.cpp`; initialization and persistence live in `sources/NxWorld/Framework/GameInstance.cpp`.
This page describes the current implementation, including migration limitations.

== Startup

. The application assigns a TemplateGameInstance to `gGameInstance`.
. It constructs EditorIntegration, which attaches itself to that instance, then Runtime bound to the same instance.
. `Runtime::run()` calls `GameInstance::initialize()`.
. Initialization creates the Platform Window, subscribes to resize events, scans assets, loads/configures shaders, and builds the component type/tag map.
. The attached integration initializes the editor. GameInstance initializes the scene and subscribes to object additions to discover a camera.
. Editor/scene cached state is read, followed by core resource loading and game extension hooks.
. Runtime enters its main loop.

`GameInstance::initialize()` does not itself enter the loop.
The application still supplies the global instance because several initialization and rendering paths use global accessors.

== Frame processing

Each frame starts a stopwatch and polls window events.
Scene/component ticks receive World's previously measured delta; the initial delta is zero.

[cols="2,4,4",options="header"]
|===
|Operation |GameOnly |Editor
|Scene tick |Runs each frame. |Runs while the application viewport is focused.
|Integration update |Calls input update if an integration is attached. |Calls integration tick, which drives the editor.
|Scene drawing |Draws with the current camera. |Updates picking, prepares the viewport target, draws the scene, and completes viewport drawing.
|GameInstance tick |Runs after scene drawing when a camera exists. |Runs after scene drawing when a camera exists.
|===

Without an active camera, scene drawing and GameInstance tick are skipped in both modes.
Scene ticking follows the separate conditions above.
Scene iterates its root objects; BaseComponent propagates ticks through children, subject to component enabled and no-tick flags.
Objects are updated, not reloaded from disk on each frame.

Runtime then throttles an unfocused/iconified window, checks the optional timeout, swaps buffers, updates FPS statistics, and stores the measured frame duration in World.
The loop ends when the window should close.

== Rendering integration

ApplicationIntegration defines editor-facing operations without requiring Runtime to include editor implementation headers.
EditorIntegration forwards these operations to GameEditor, the picker, and the viewport render target.
Scene draws its objects using the active camera, with editor grid and optional skybox/mesh behavior.

Editor and GameOnly operate on the same scene.
Changing render mode does not snapshot gameplay, reset world state, or restore an authored scene.
It should not be treated as isolated Play/Stop behavior.

== Shutdown

After the loop, Runtime calls `GameInstance::saveAllToCache()`.
This writes attached editor state and the scene, then invokes the game's save hook.
In the example, EditorIntegration is destroyed and detached before `gGameInstance` is reset.
The integration pointer is non-owning; callers must preserve that lifetime ordering.

See xref:draft--new-architecture.adoc#_migration_boundaries[Migration boundaries] for the remaining lifecycle and persistence work.
