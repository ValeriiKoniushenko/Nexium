= Module Graph

A source directory can produce several libraries. The tables follow `sources/*/CMakeLists.txt`.
Dependencies may skip layers; numbering describes their intended direction.

== Source layers

[cols="1,2,5",options="header"]
|===
|Layer |Directory |Responsibility
|8 |Editor |ImGui windows, property adapters, selection, picking, gizmos, toasts, asset tools, viewport integration.
|7 |NxRuntime |Frame loop, timing, input-context switching, startup/save orchestration.
|6 |NxWorld |GameInstance, World state, input routing and controllers, framework managers, Scene, actors, cameras, rectangles, animation, optional meshes.
|5 |NxSubsystems |AssetsManager, shaders/graphics data, text rendering, input actions and types, optional Assimp importer.
|4 |NxFundamental |Component trees, transforms, tags, serialization, asset abstractions, atlases.
|3 |RawBackend |CPU images, OpenGL textures/framebuffers, drawable interface, FreeType access.
|2 |Platform |Window, keyboard/mouse, OpenGL access.
|1 |Foundation |Configuration, logging, data/outline interfaces, latency instrumentation, Utils core access.
|===

Private module logging targets are omitted.

Platform Input privately links Platform Graphics and Core::Stb.
All three RawBackend targets privately link Core::Stb.
Subsystem Graphics privately links RawBackend Fonts and Utils::Utils, so FreeType stays
behind the `NX::Face` abstraction.
AssimpImporter privately links assimp::assimp; World additionally exposes Assimp and the importer when 3D is enabled.
AssetsManager privately links comdlg32 on Windows.
Editor privately links imguizmo::imguizmo.

`Nexium::Fundamental` is an INTERFACE aggregate of its six focused targets, including
`Nexium::Fundamental::Utils`.
`Nexium::NxFundamental`, `Nexium::NxWorld`, and `Nexium::NxRuntime` preserve old aliases.
`Nexium::World::Scene` aliases World; it is not a separate scene library.
There is no combined `Nexium::RawBackend` target: link the Graphics, Fonts, or Common
target you actually need.

The application chain is `TemplateGame -> Editor -> Runtime -> World`.
TemplateGame retains Editor with WHOLE_ARCHIVE.
WHOLE_ARCHIVE retains otherwise unreferenced component registrations in these static libraries.

== Runtime ownership

[cols="2,5",options="header"]
|===
|Owner or observer |Current relationship
|`gGameInstance` |Application-owned unique pointer to GameInstance.
|GameInstance |Owns gameScene, world, assets, userInterface as members; references the shared ShaderManager and Platform Window.
|Runtime |Borrows GameInstance by reference.
|EditorIntegration |Borrows Runtime; owns GameEditor, ObjectSelectorManager, ObjectPickerAggregator.
|GameInstance integration pointer |Borrows ApplicationIntegration; attachment/detachment is explicit.
|World |Owns lighting/time and game/player/level state; observes currentCamera. Scene is its sibling, not its child.
|`InputSystem` |Singleton; holds non-owning InputController pointers per context. Controllers unregister themselves on destruction.
|Scene |Owns root SceneObjects through intrusive pointers, plus grid/skybox state.
|BaseComponent |Owns children through intrusive pointers; observes its parent.
|ObjectSelectorManager |Holds strong pointers to selected components, keyed by addresses.
|===

Source anchors: `Framework/{GameInstance,World}.h`, `Scene/Scene.h` in NxWorld,
`NxFundamental/ECS/BaseComponent.h`, and `Editor/EditorIntegration.h`.

== Boundary limits

`ApplicationIntegration` lets Runtime and World call editor hooks without including Editor implementation headers.

RawBackend's `IDrawable` still names higher-layer camera/actor/mesh types through forward declarations.
`Scene::directDraw` receives the skybox and grid programs from Runtime, but still reaches the
camera through `GetWorld()` and the render mode through the global `gGameInstance`.
`InputSystem` is a `Core::Singleton`, so input routing is global rather than owned by a session.

Public header sets support compilation checks, but the shared `sources/` include root also exposes private headers.
“Subsystem” currently means a service library, not automatic lifetime management.

See xref:build:cmake-structure.adoc[CMake infrastructure] and xref:ue5-alignment.adoc[recommended boundaries].
