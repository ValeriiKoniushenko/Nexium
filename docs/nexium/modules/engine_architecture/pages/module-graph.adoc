= Module Graph

The xref:draft--new-architecture.adoc#_layer_map[layer map] and xref:draft--new-architecture.adoc#_build_modules[target tables] describe the current build graph.
The previous diagram represented the pre-migration architecture and is no longer used as the current module map.

[cols="2,5",options="header"]
|===
|Consumer |Main dependencies
|TemplateGame |Editor, retaining its static archive with whole-archive linkage.
|Editor |Runtime and ImGui.
|Runtime |World, retaining its component registration translation units.
|World |World Animation, Fundamental, Subsystems, Platform, RawBackend.
|Subsystems |Focused Fundamental, Platform, Foundation, and RawBackend targets.
|Fundamental |Foundation; asset-related targets additionally consume graphics/atlas dependencies.
|RawBackend |Foundation and Platform Graphics.
|Platform |GLFW, Glad, Utils core, JRM adapter, and GLM as required by each target.
|Foundation |Utils core, spdlog, JRM adapter.
|===

These are dependency groups, not complete link lines; the draft records narrower target boundaries.
One source directory may produce several libraries, and compatibility aliases do not create additional modules.

== Ownership is a separate graph

GameInstance owns Scene and World as siblings, together with AssetsManager and UserInterface.
Runtime references GameInstance.
EditorIntegration owns the editor tools and attaches through a non-owning ApplicationIntegration pointer.
Scene owns its root component trees; World references the active camera.

See xref:draft--new-architecture.adoc#_object_model_and_ownership[Object model and ownership] and xref:lifecycle.adoc[Application Lifecycle].
