= Architecture Overview
:page-role: landing

Nexium is a personal game engine and ImGui editor for a small development team.
The current architecture separates Foundation, Platform, RawBackend, Fundamental, Subsystems, World, Runtime, and Editor into CMake modules.
The implementation is migrating toward clearer ownership and dependency boundaries, with 2D as the immediate focus.

== Current architecture

The xref:draft--new-architecture.adoc[migration draft] describes the implemented modules, public targets, ownership, reflection, persistence, and unfinished contracts.
It replaces the earlier overview based on `GameplaySystem` and an editor owned directly by GameInstance.

* xref:module-graph.adoc[Module relationships] distinguishes build dependencies from object ownership.
* xref:lifecycle.adoc[Application Lifecycle] follows startup, frame processing, and shutdown.
* xref:ecs-overview.adoc[ECS Overview] covers the component system in more detail.

== Design direction

Prefer focused libraries and explicit ownership over additional framework layers.
The reflected component tree supports gameplay composition and editor authoring through JustReflectMe.
Runtime accesses editor behavior through ApplicationIntegration, while Editor depends on Runtime.

The current example still links Editor, and several framework classes remain scaffolding.
The migration draft marks these distinctions so planned capabilities are not mistaken for implemented behavior.
