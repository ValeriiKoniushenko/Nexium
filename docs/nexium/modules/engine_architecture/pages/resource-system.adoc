= Resource System

AssetsManager belongs to NxSubsystems; asset abstractions belong to NxFundamental.
NX::GetAssetsManager resolves the manager through gGameInstance.
There is no separate GetBlueprintManager in the current API.

== Indexing and lookup

AssetsManager initially registers Config::Path::data, not only data/assets.
initScanFileSystem clears its asset indexes and scans registered roots.
refreshFilesSystem rescans and removes missing entries only when the scan completes successfully.

IDs are normalized paths relative to the compiled project root, including extensions.
For example, an asset under data/assets remains identified with that prefix.
Extra roots can be registered; outside-project paths can resolve through relative parent segments.
The current index has no independent stable asset ID or mount namespace.

[cols="2,5",options="header"]
|===
|Resource |Current path
|.nx |ECSAsset; metadata and serialized component template.
|.nxtex |TextureAsset through BaseAsset/AssetRef; GPU texture loads on consumer request.
|Images |Asset browser classifies image files; TextureAtlas separately reads images for atlas generation.
|Shaders |ShaderManager scans/configures shaders through its own service.
|Skyboxes |Types and drawing exist, but AssetsManager::getSkybox is a stub and scan registration is commented out.
|3D models |Optional mesh/import functionality; not a universal resource registry.
|===

File-browser classification does not imply loader support for every displayed extension.
Atlas generation is synchronous and belongs to AssetsManager's current initialization/resource workflow.

== Two asset contracts

[cols="2,5",options="header"]
|===
|API |Behavior
|ECSAsset / NXECSAsset |Manager-held intrusive asset object; tracks metadata/status and a loaded component template.
|getEcsAsset |Returns a strong asset reference; reference-count hooks can load the template.
|getWeakEcsAsset |Observes the indexed asset without requesting its loaded component data.
|getUniqueEcsAsset |Reconstructs separate component data from the asset file, including its optional adapter.
|BaseAsset / AssetRef |Separate resource contract with explicit load/unload requests; used for TextureAsset.
|NXSceneAsset |Pairs a template asset reference with instance component data; separate from the main Scene container.
|===

ECSAsset statuses are NotLoaded, PreLoaded, Loaded, PreLoadingError, and LoadingError.
Preloading reads metadata; loading reconstructs the component through GlobalComponentFactory.
ECSAssetImpl supplies optional resource-specific load/unload work.

BaseAsset/AssetRef keeps one index reference and loads payload on the first consumer;
the last consumer releases the payload while the indexed object remains.
This is resource residency management, not background streaming.
ECSAsset and BaseAsset use different serialization/error contracts and remain separate APIs.

== Templates and instances

The editor calls serialized component templates “Blueprints.”
They are prefab-like authoring data; no visual scripting VM or generated gameplay graph exists.

Spawning through Scene::addBlueprintObjectToScene requests unique component data and records the asset path.
Editing a scene instance and editing the source template are different operations.
A source template change can affect a reconstructed asset-backed instance;
a complete generic property-override/rebase system is not implemented.

Scene format version 1 saves each root's name, transform, asset type/reference, and type-specific data.
Objects without an asset reference additionally save a reflected componentData tree.
Asset-backed objects are reconstructed from their template and then receive the existing overrides.
Unversioned asset-backed documents remain readable; unsupported versions are rejected.

Loading reconstructs and validates incoming roots before replacing the current roots.
Bad records or unresolved references preserve the existing roots.
This does not provide a general rollback of resource loading or initialization side effects.

== Authoring reliability

CacheSystem writes Scene under data/scenes and World under data/world.
These are persistent authoring/state files, not disposable caches.
xref:file-io.adoc[File I/O] describes replacement and failed-load protection.

The browser's rename path renames the filesystem entry and refreshes the index.
It does not rewrite saved scene/template references.
Moves, deletion, stable IDs or redirects, and dependency reporting need an explicit authoring contract.

See xref:ue5-alignment.adoc[UE5 comparison] for the proposed resource boundary.
