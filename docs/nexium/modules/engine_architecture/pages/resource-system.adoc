= Resource System

`NX::GetAssetsManager()` accesses the current game's asset manager in NxSubsystems.
It indexes asset files, then loads their contents synchronously when requested.
The asset abstractions live in NxFundamental.

== Indexing and lookup

`initScanFileSystem()` clears the indexes and recursively scans registered roots;
the default root is `Config::Path::data` (all of `data/`).
`registerNewAssetPath()` adds a root; scan or refresh afterward to index it.

An asset's logical ID is its normalized path relative to the compiled project root,
including the extension: for example, `data/assets/actor.nx`.
Use interned `Core::StringAtom` IDs (`_atom` for literals).
`getEcsAsset`, `getWeakEcsAsset`, and `getUniqueEcsAsset` require the exact ID;
the `getEcsAssetByPath` / `getWeakEcsAssetByPath` variants normalize filesystem paths.
External roots can produce IDs containing `..`; there are no stable UUIDs or mount aliases.

[cols="2,5",options="header"]
|===
|Resource |How it loads
|`.nx` |`ECSAsset`: metadata first, component template on request.
|`.nxtex` |`TextureAsset`: descriptor first, image and GPU texture on request.
|Raw images |`TextureAtlas` reads images separately during synchronous atlas generation.
|Shaders |Managed separately by `ShaderManager`.
|Skyboxes |Not indexed; `getSkybox()` is unimplemented.
|===

Only `.nx` and `.nxtex` are indexed. A file appearing in the browser does not imply loader support.

== Choosing a reference

[cols="2,5",options="header"]
|===
|API |Behavior
|`getWeakEcsAsset` |Observe metadata without loading component data.
|`getEcsAsset` |Get an `NXECSAsset` strong reference to the shared component template.
|`getUniqueEcsAsset` |Reconstruct independent component data from disk, including optional adapter loading.
|`getTexture` |Get an `NXTexture` (`AssetRef<TextureAsset>`) for a `.nxtex` descriptor.
|===

While indexed, both asset systems keep one manager reference. The first consumer reference
loads the payload; releasing the last consumer unloads it while keeping the indexed object.
Unique ECS loads return separate component data without loading the shared template.

For `.nx`, preloading reads `type`, `name`, and `tags`; loading reconstructs `data`
through `GlobalComponentFactory`. An optional `ECSAssetImpl` handles `assetData`.
Missing IDs return empty references. A valid reference does not guarantee a successful load:
check `getLoadingStatus()` for `Loaded`, `PreLoadingError`, or `LoadingError`.
Unique loading can throw.

Textures use the separate `BaseAsset` / `AssetRef` contract.
The descriptor's `AssetData` stores the image path and vertical-flip setting;
the image path is relative to the project root, not the descriptor's directory.
`BaseAsset::isLoaded()` reports reference count, not GPU-load success.

== Refreshing and editing

`refreshFilesSystem()` rereads descriptors and reloads ECS templates with active strong references.
It removes missing entries only if filesystem traversal succeeds for all roots.
Texture descriptors are reread, but existing GPU textures are not automatically reloaded.

The editor calls ECS templates “Blueprints.” `Scene::addBlueprintObjectToScene`
creates independent component data and records the template path.
Editing an instance does not edit its template; refreshing a template does not update existing instances.

On scene reload, asset-backed roots are reconstructed from their templates, then receive
saved names, transforms, and type-specific data. Roots without an asset reference store a
full `componentData` tree. General property overrides are not implemented.

Renaming a file changes its logical ID. The browser refreshes the index but does not rewrite
saved references, so update those references too.

Scenes in `data/scenes` and worlds in `data/world` are persistent authored files.
See xref:file-io.adoc[File I/O] for save behavior and failed-load protection.
