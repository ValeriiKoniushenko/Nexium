= File I/O

`Foundation::IDataIO` defines an object's storage directory and name.
`NX::CacheSystem`, declared in `NxFundamental/ResourceManagement/DataStream.h`, reads/writes JSON.
Its “cache” includes persistent authored content.

== Locations

[cols="2,4",options="header"]
|===
|Data |Path relative to the compiled project root
|Scene |`data/scenes/<sanitized scene name>.json`
|World, including the start scene |`data/world/<sanitized world name>.json`
|Window |`data/cache/RootWindow.json`
|Editor scene tabs |`data/cache/SceneTabs.json`
|Input managers |`data/Inputs/<manager hash>.json`
|Editor objects |Object-specific directories beneath `data/`
|ImGui layout |`data/cache/windows.ini`
|Assets |Their attached source files; see xref:resource-system.adoc[Assets].
|===

CacheSystem combines `Config::Path::data`, `getCacheDir()`, and a sanitized `getCacheHash()`
with `.json`. `IDataIO::getCacheDir()` defaults to `cache`, so a type that does not override
it lands in `data/cache/`. Non-alphanumeric characters other than `_` become `_`, so names can collide.
Paths derive from `NEXIUM_PROJECT_DIR` compiled into Foundation.

== Reads and failures

`read()` parses JSON and calls the object's deserializer, or JRM when none is supplied.
Exceptions are logged and mark the path as a failed read.
`tryRead()` returns whether a file existed and reading was attempted, not whether it succeeded.

A failed read blocks *automatic* CacheSystem writes to that path until a successful read,
a successful explicit write, or `clearCache()`.
`CacheWriteMode::Automatic` is the default and is used for shutdown saves.
`CacheWriteMode::Explicit` is used by *Save all* (menu and shortcut). It writes anyway and
clears the failed-read mark, which is how a user recovers a file they have fixed in the editor.
This guard is specific to CacheSystem; the asset readers use separate error handling.
Optional reflected-field errors can be logged without rejecting the document.

Scene validates and reconstructs incoming roots before replacing existing ones.
Malformed records preserve the old roots, but resource/initialization side effects are not rolled back.
`SceneManager` adds a stricter rule on top of CacheSystem: a scene writes, moves, or deletes only
the file it loaded or wrote itself. A scene file that failed to import is skipped and never touched,
even by an explicit save.
See xref:gameplay:scenes.adoc[Scenes] for the saved format and import rules.

== Writes

CacheSystem and both asset save paths use `WriteFileAtomically`: create an exclusive sibling
temporary file, write/flush/close, then replace the destination.
A failed replacement preserves the old destination and removes the owned temporary file.
There is no multi-document transaction or cross-platform durable-sync guarantee.

`CacheSystem::write()` returns `false` when a write is blocked, its directory cannot be created,
or replacement fails; each case is logged. Serialization errors can still escape before replacement.
`SceneManager::writeToCache()` reports whether every scene was saved, but
`GameInstance::saveAllToCache()` ignores these results, so editor save notifications still do not prove success.

`BaseAsset` updates existing JSON through `ioFieldsUpdate()`.
The generic `DataStream::field()` output assignment is disabled; use the implemented serializers,
not that helper, when persisting new data.

Implementation: `ResourceManagement/{DataStream,AtomicFile}.{h,cpp}` in NxFundamental.
`AtomicFileTests.cpp` covers replacement, failed-load protection, and explicit-save recovery;
`ScenePersistenceTests.cpp` covers scene reconstruction, rejected documents, skipped files, and file ownership.
