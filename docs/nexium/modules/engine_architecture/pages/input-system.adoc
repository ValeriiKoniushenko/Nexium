= Input System

Platform supplies window events, keyboard/button state, cursor position, and drag tracking.
`NxSubsystems/Input` maps that state to named actions in namespace `NX`.

== Actions

`KeyboardInputManger` and `MouseInputManger` own intrusive action references indexed by
`Core::StringAtom` names. “Manger” is the current API spelling.
`getOrCreate()` reuses the existing name; it does not change that action's key binding.

`InputAction::update()` polls its key, applies repeat/frequency limits, snapshots left
Shift/Alt/Ctrl, and passes that snapshot to `onPress`.
Repeat defaults to enabled with zero delay. Disable repeat for one notification per press;
frequency limits use elapsed `system_clock` milliseconds.

Mouse actions also provide:

* `onMouseClick`: current position on a qualifying press, using the same repeat policy.
* `onMove`: position delta after the first sample establishes a baseline.
* `onDrag`: position delta while Platform reports dragging and the action's button condition matches.

A mouse click here is a press notification, not release detection.

== Who updates actions

[cols="2,4",options="header"]
|===
|Owner |Update path
|GameEditor |Keyboard and mouse mappings after drawing editor windows.
|EditorIntegration in GameOnly mode |Editor keyboard mappings only.
|Spectator |Its own keyboard and mouse mappings during its scene tick.
|===

Editor scene ticks require viewport focus. There is no central input-context stack or
consumption/priority policy; callers must gate actions where needed.

Editor shortcuts in `GameEditor::setupShortcuts()` are F1 (render mode), Escape (clear selection),
F12 (close), and left Ctrl + left Shift + S (save).
Render-mode switching uses the same scene; see xref:lifecycle.adoc[Application Lifecycle].

Implementation: `NxSubsystems/Input/InputAction.{h,cpp}`, `InputManager.h`,
`Editor/GameEditor.cpp`, and `NxWorld/Scene/Spectator.cpp`.
