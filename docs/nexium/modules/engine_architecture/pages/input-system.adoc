= Input System

Platform supplies raw Window, Keyboard, Mouse, and DragAndDrop state.
NxSubsystems supplies named keyboard/mouse actions.
These APIs currently live in NX and Platform, rather than the old Core input namespace.

== Actions and mappings

[cols="2,5",options="header"]
|===
|Type |Responsibility
|NX::InputAction<KeyT> |Optional key binding, name, repeat/frequency state, modifier snapshot, onPress.
|KeyboardInputAction / KeyboardIA |Polls Platform keyboard state.
|MouseInputAction / MouseIA |Button press/click, cursor movement, drag notifications.
|InputManger<InputT> |Name-to-action mapping, lookup/create/remove, per-action update.
|KeyboardInputManger / MouseInputManger |Concrete mapping managers; “Manger” is the current API spelling.
|===

getOrCreate returns an existing mapping by name or creates one for the key.
Action names use Core::StringAtom; action references use Core intrusive pointers.

InputAction::update checks the bound key.
It triggers onPress when the press transition/repeat policy and frequency permit,
then snapshots modifier keys.
Repeat is enabled by default.
Frequency uses system_clock elapsed milliseconds; no monotonic input clock is supplied.

MouseInputAction first updates button state, then cursor state.
The first cursor sample establishes its baseline.
Movement triggers onMove; onDrag depends on Platform DragAndDrop state and the bound button.
onMouseClick reports current cursor position through the action's private press delegate.
It is a press notification, not a separate release/click-duration recognizer.

== Current routing

GameEditor owns keyboardInput and mouseInput and updates them while its editor update runs.
EditorIntegration::updateInput updates editor keyboard mappings in the GameOnly path.
Spectator owns and updates its own keyboard/mouse mappings through its scene tick.

Editor scene ticking depends on viewport focus.
The current routing is not a central input-context stack with consumption or priorities.
ImGui interaction, editor shortcuts, camera controls, and game input can require separate gating.

In GameEditor::setupShortcuts, F1 toggles render mode and Escape clears selection.
The save binding checks both left Ctrl and left Shift with S.
Render-mode switching does not start a separate gameplay session.

== Recommended contract

Separate editor-global shortcuts, viewport navigation, and active-game input contexts.
Route input before simulation and define focus/capture behavior explicitly.
A text field should consume typing; playing should give game controls the intended viewport focus.

Preserve the current action/delegate API until a real game needs richer mapping.
Remapping persistence, gamepad support, and a general UE Enhanced Input equivalent are not established features here.
