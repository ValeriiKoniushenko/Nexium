[[ecs-components]]
= Component System

Nexium's ECS is a reflected object/component tree.
It provides composition, cloning, type factories, and traversal.
There is no archetype/chunk storage or central query scheduler in this implementation.

== Main types

The component API is declared in `NxFundamental/ECS/BaseComponent.h`, in namespace NX.

[cols="2,5",options="header"]
|===
|Type |Role
|AbstractComponent |Intrusive reference counting, enable/no-tick flags, casting, reflection serialization, tick dispatch.
|BaseComponent |Named/typed tree node; intrusive child ownership, borrowed parent, initialization, traversal, cloning.
|GlobalComponentFactory |Process-wide name-to-creator/type/tag maps.
|SceneObject |BaseComponent plus Transformable, IDrawable, IOutliner, and IDataIO.
|Actor |SceneObject subclass; currently a thin extension rather than a separate gameplay ownership model.
|BaseCamera |Actor subclass; OrthographicCamera/PerspectiveCamera provide projection behavior.
|Rectangle / RectangleAnimated |Scene objects for 2D drawing and animation.
|NX::Gui::Widget |Editor component using the same tree machinery for ImGui presentation.
|===

Scene owns root SceneObjects.
An object can have non-spatial BaseComponent children.
Transformable behavior is supplied separately and composed into SceneObject.
Node inheritance and tree attachment serve different purposes.

== Registration and reflection

[cols="3,5",options="header"]
|===
|Macro |Current purpose
|CLASS / ENUM_CLASS / FIELD |JRM annotations for metadata generation.
|ECS_DECL |Component declaration, JRM bridge, typed pointers, Create/clone, default constructor.
|ECS_DECL_NO_CNSTR |Declaration with a caller-defined constructor.
|ECS_DECL_NO_SER |Declaration variant without generated component serialization bridge.
|ECS_DECL_NO_SER_NO_CNSTR |Combines both declaration variants.
|ECS_IMPL |Out-of-line reflection bridge, component type definition, creator and clone implementation.
|ECS_IMPL_NO_SER |Implementation variant without that serialization bridge.
|ECS_TEMPLATE_COMPONENT_DECL / ECS_TEMPLATE_COMPONENT_IMPL |Template-component variants.
|===

Use the component macros instead of a hand-maintained registry list.
ECS_IMPL initializes componentType through a static initializer that registers a creator with GlobalComponentFactory.
The current component macros do not implement linker-section registration.
WHOLE_ARCHIVE linkage preserves otherwise unreferenced registration translation units.

JRM-generated reflection and factory registration are cooperating mechanisms, not the same registry.
Generated files are produced during the build and must not be edited manually.
The adapter lives in `dependencies/JustReflectMe/sources/JustReflectMe/Adapter.h`.
Native C++ reflection is not used.

Non-template component type names are serialized identifiers.
Renaming a C++ type or changing its macro-generated identifier needs a content migration.
Template registration uses typeid names; those are unsuitable as portable saved-content identifiers.

== Lifecycle and composition

AbstractComponent::tick dispatches when enabled and not marked no-tick;
it does not itself require initialization.
BaseComponent::initialize invokes pre-initialize/initialize hooks once, then initializes children.

BaseComponent's default onTick visits child components.
A derived onTick can replace this behavior; call the base hook when child propagation is required.
A no-tick parent therefore also stops the default child tick path.

Adding a child establishes ownership and its parent link.
Attaching an existing child through attachChildComponent clones it.
Copying component trees clones descendants; detached/removed surviving children lose their parent links.
Generated concrete clone methods invalidate the result for later initialization.
This does not guarantee that every derived component safely duplicates external resources or live subscriptions.

Traversal supports BFS/DFS and type/name lookups.
The forEach traversal and child lookup helpers exclude the starting node.
getOwner identifies the topmost component ancestor; it does not identify a World context.

== Persistence and identity

Reflected fields store component state and child trees.
Scene records additionally store transforms, names, asset references, and type-specific overrides.
xref:resource-system.adoc[Resource persistence] distinguishes templates from scene instances.

Component names are editable labels.
makeHash depends on the node's name and ancestor names.
Neither names, that mutable hash, nor pointer addresses provide durable object identity across
reload, rename, reparenting, or a future Play-session clone.

Keep the tree model for authoring.
Introduce stable IDs and explicit World context when reference persistence and simulation need them;
a data-oriented storage rewrite requires measured workload evidence.

== Existing checks

`tests/ECSTests/ECSTests.cpp` exercises serialization, factories, copying, traversal,
parent repair, attachment, and removal.
`tests/Runtime/RuntimeTests.cpp` checks Runtime binding and retained World registrations.
These checks do not prove Play-session isolation or mutation safety during a tick.
