= Threading

Scene ticks, editor updates, asset loading, and OpenGL rendering run sequentially on the
main thread. There is no runtime job scheduler or separate render thread.
File scans, JSON reconstruction, shader compilation, and atlas generation block their caller.

Keep GPU resource creation and destruction within a valid OpenGL context.
Reference counting does not make component trees, registries, or resource payloads thread-safe.

== Build-time concurrency

CMake can compile targets in parallel. JRM is a separate build tool.
`cmake/RunJRM.cmake` locks `.cache/nexium-codegen/lock` while generating shared source-tree files.
This serializes generator writers across build directories, but does not isolate compilers
from another build's generated-header changes.

Background loading remains future work: CPU decoding could run in workers, with GPU uploads
and scene/editor changes applied at a defined main-thread point.
