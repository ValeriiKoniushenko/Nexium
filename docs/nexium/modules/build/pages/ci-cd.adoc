= Continuous Integration

== What the workflow runs

`.gitea/workflows/code-quality.yml` defines a single `Build` job that runs *on pull
requests* using the `linux` runner and the `cpp-ci:latest` container. There is no build
matrix: the job checks out the repository twice and drives two Debug configurations
sequentially, GCC first and Clang second.

All step commands are thin wrappers. Repository-specific values live in
`.gitea/ci-config.sh`, and the executable logic lives in the `scripts` submodule under
`scripts/ci/gitea/`. `scripts/ci/gitea/runners/run_ci_check.sh <config> <check>` dispatches
every named check, so the workflow file itself contains no tool invocations.

[cols="2,5",options="header"]
|===
|Step |What it does
|Init submodules |Fetch `scripts` shallowly, then `prepare_checkout.sh` for the bootstrap and cached submodules named by `CI_BOOTSTRAP_SUBMODULES` / `CI_CACHED_SUBMODULES`.
|CI helper tests |`python3 -m unittest discover -s scripts/ci/gitea/tests`.
|Copyright |`copyright` and `publish-copyright` checks; failures are recorded, not fatal yet.
|Clang-format |`format` check; failure is recorded, not fatal yet.
|Configure GCC Debug |`configure_variant.sh ... gcc`.
|Clang-tidy |`tidy` against the GCC build directory with `--fail-on error`, under a 10-minute step timeout.
|Build GCC Debug |`build_variant.sh ... gcc`.
|Configure/Build Clang Debug |The same two scripts against the second checkout.
|Capture TemplateGame UI |`capture-ui` runs the built game headless and publishes `template-game-ui.png`.
|Unit tests |`tests` runs `bin/Nexium_Tests` directly.
|Coverage |`configure_coverage.sh`, then the `coverage` check builds the `Nexium_Coverage` target; `publish-coverage` posts the report and the job summary quotes `summary.txt`.
|Unit tests under Valgrind |`valgrind-tests`.
|Headless game under Valgrind |`valgrind-game` with `NEXIUM_HEADLESS_GL=1` and `data/cache/RootWindow.json`.
|Precheck results |Final step that fails the job if the copyright or clang-format checks failed earlier.
|===

Both configurations are Debug with `NEXIUM_DISABLE_TESTS=OFF`,
`NEXIUM_DISABLE_BENCHMARKS=ON`, `NEXIUM_ENABLE_3D_MODULE=OFF`, and both
`NEXIUM_VERIFY_INTERFACE_HEADER_SETS` and `NEXIUM_ENABLE_LAYER_CHECKS` set to `ON`.
The coverage configuration adds `NEXIUM_ENABLE_CODE_COVERAGE=ON` and turns the
header/layer checks off. CTest is not configured for this project.

== Timeouts and runner requirements

Checks carry their own timeouts inside `run_ci_check.sh`: unit tests three minutes,
unit Valgrind five minutes, the headless game under Valgrind eight minutes (the game
itself stops after `CI_GAME_TIMEOUT_SECONDS`, currently 5), the UI capture two minutes,
and the coverage build 45 minutes. Clang-tidy has a 10-minute timeout in the workflow.

The job depends on persistent runner volumes: `/ccache` for compiler caches,
`/cache/build` for build directories, and a git-repo cache. Build directories live
outside the checkout (`/cache/build/{gcc,clang}/debug`, `/cache/build/gcc/coverage`),
so CI paths do not match a local `build/` layout.

The container must provide GCC, Clang, CMake 3.30+, Ninja, Python 3, clang-format,
clang-tidy, Valgrind, Xvfb, gcovr/gcov, and the engine's Linux graphics dependencies.
`cpp-ci:latest` does not pin compiler versions; configuration prints the selected version.
`GITEA_TOKEN` is required by the steps that publish review comments, the coverage report,
and the captured screenshot.

This describes configured coverage, not a passing-run guarantee. There is no push-triggered
build, no Release configuration, no benchmark job, no 3D-enabled job, no Windows job, and
no sanitizer job. See xref:cmake-structure.adoc[CMake infrastructure] for local targets and
limitations.
