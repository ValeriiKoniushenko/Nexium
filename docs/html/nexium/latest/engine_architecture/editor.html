Editor Structure

The Editor layer is the top of the module graph. It depends on Runtime and ImGui, and nothing below it includes editor headers: Runtime and World reach the editor only through the ApplicationIntegration interface.

Entry points

Object Role

EditorIntegration

Implements ApplicationIntegration. Borrows Runtime, owns the three objects below plus SceneTabsCache, and attaches/detaches itself from GameInstance.

GameEditor

Owns the ImGui setup, the window list, toast notifications, the polled input managers, and the scene render target (sceneRenderTarget).

ObjectSelectorManager

Holds strong references to selected components, keyed by address.

ObjectPickerAggregator

Chooses a picking strategy and dispatches pick requests.

GetEditorIntegration(), GetEditor(), GetObjectSelectorManager(), and GetObjectPicker() are global accessors over the integration instance, so editor code reaches these services without being handed them.

EditorIntegration maps the Runtime hooks onto GameEditor: tick() draws the windows, updateInput() updates the polled keyboard manager, updateSceneInteraction() services pick requests, isViewportFocused() forwards to the GameViewportEWC window, beforeSceneDraw()/afterSceneDraw() bind and unbind the scene target through RenderTargetToTexture::callMePreDraw() / callMeAfterDraw(), and readFromCache()/writeToCache() persist editor state, the open scene tabs (data/cache/SceneTabs.json), and the ImGui layout in data/cache/windows.ini. The integration also subscribes to SceneManager::onCurrentSceneChanged and clears the selection whenever the current scene changes.

Windows are discovered, not listed

Editor windows derive from BaseEWC (Windows/BaseWindow.h) and are reflected components tagged Tag_EditorWindow. GameEditor::initialize() asks GlobalComponentFactory for every type carrying that tag, creates one instance of each, and registers it. Adding a window means adding a tagged component type; there is no central window list to edit.

registerNewWindow() records the type, appends the instance, and opens or closes it according to the requested initial state. Windows are looked up by type, optionally filtered by a regex over the window title: getWindow<T>(), showWindow<T>(), tryToOpenWindow<T>(). TemplateGame links Editor with WHOLE_ARCHIVE so these registrations survive linking.

Current windows include the root dock, menu bar, scene tree, object properties, assets explorer, game viewport, logs, world settings, editor settings, a shader inspector, an image viewer, asset/ECS search, blueprint-creation and scene-delete modals, and the asset editors under Windows/Editors (texture, text, input bindings). Windows/ECSAdapters holds the per-component property adapters, and GuiComponents holds the reusable ImGui widgets, including SearchableComboBox, a combo with a filter box and optional per-row actions.

Scene windows

Windows/Scenes/ holds the scene-facing UI; scene behavior itself lives in SceneManager (see Scenes).

Piece Role

SceneTabs

Drawn at the top of the game viewport: a Scenes picker over every loaded scene, a per-row delete button, a New button, and a tab per open scene.

SceneTabsCache

Saves and restores the open tabs and selected tab. Editor-only: the game starts from World::startScene and never reads it.

SceneDeleteConfirmation

Modal that asks before removeScene(). It closes itself if the scene disappears meanwhile and disables Delete for the last scene.

SceneTreeWindowEWC

Shows the current scene’s tree. It renames the scene on commit, toggles the start scene, and defers delete/duplicate until the tree traversal ends.

The game viewport separates its window from its canvas, the area below the scene tabs. getCanvasPosition() and getCanvasSize() describe that area. When it changes size, onCanvasSizeChanged resizes sceneRenderTarget, and picking maps the mouse into the canvas.

Selection, picking, and gizmos

ObjectPickerAggregator owns two strategies: SlowObjectPicker, which renders object identifiers to a target and resolves the colour under the cursor, and RectangleBasedObjectPicker. Picking is request-based — requestPick(callback) records the request and update(scene) services it on the next interaction pass — and works for both camera projections.

SceneGizmo is a member of the game-viewport window. It draws the ImGuizmo manipulator for the selected object inside the viewport rectangle and reports blocksPicking() so a drag on the gizmo is not treated as a pick. SceneGizmo::ApplyTransform() converts the manipulated world matrix back into the object’s local transform. The gizmo is checked by tests/Editor/SceneGizmoTests.cpp.

Selection holds strong references, so a selected object outlives removal from the scene. Changing the current scene clears selection; removing an object does not. See Memory and Ownership.

Known gaps

  • There is no command/undo layer: property edits, transforms, and create/delete apply directly.

  • There is no Play/Stop control. Render-mode switching (F1) shares the authored scene, so gameplay edits are editor edits; see Application Lifecycle.

  • Save notifications are raised without verifying that every write succeeded; see File I/O.

Implementation: sources/Editor/. Checks: tests/Editor/.
