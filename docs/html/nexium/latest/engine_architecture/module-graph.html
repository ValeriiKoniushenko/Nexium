Every target links only the targets whose headers its own sources include; there are no umbrella or aggregate targets, so link exactly the focused target you need. Dependencies needed only by a .cpp file are private, for example Core::Stb, Platform Graphics and Platform Resources in Platform Input, RawBackend Fonts and Utils::Utils in Subsystem Graphics, and Foundation Debug in World and Runtime. AssimpImporter privately links assimp::assimp; when 3D is enabled World and Editor expose assimp::assimp and privately link AssimpImporter/AssimpMisc. AssetsManager privately links comdlg32 on Windows. nlohmann/json.hpp is a system header and has no CMake target. Known layering violation: Subsystem::Graphics (Font.cpp) includes NxWorld/Entities/Camera/Camera.h without linking World, because that would be a cycle. Editor::GuiComponents likewise only uses the header Editor/IconsFontAwesome.h. No target name is also a prefix of another target: each module’s root-folder library is named <Module>::Base (Foundation, World, Runtime, Editor) next to its nested libraries, and there is no combined Nexium::RawBackend or Nexium::Fundamental target.

The application chain is TemplateGame → Editor → Runtime → World. TemplateGame retains Editor with WHOLE_ARCHIVE. WHOLE_ARCHIVE retains otherwise unreferenced component registrations in these static libraries.

Source anchors: Framework/{GameInstance,World}.h, Scene/Scene.h in NxWorld, NxFundamental/ECS/BaseComponent.h, and Editor/EditorIntegration.h.

Boundary limits

ApplicationIntegration lets Runtime and World call editor hooks without including Editor implementation headers.

RawBackend’s IDrawable still names higher-layer camera/actor/mesh types through forward declarations. Scene::directDraw receives the skybox and grid programs from Runtime, but still reaches the camera through GetWorld() and the render mode through the global gGameInstance. InputSystem is a Core::Singleton, so input routing is global rather than owned by a session.

Public header sets support compilation checks, but the shared sources/ include root also exposes private headers. “Subsystem” currently means a service library, not automatic lifetime management.

See CMake infrastructure and recommended boundaries.
