Architecture Overview

Nexium is a personal game engine and editor for games made by 1–3 developers. Games currently live in the engine repository. The immediate goal is a useful 2D authoring workflow; optional 3D and game-only delivery can follow.

Reading the architecture

  • Module graph maps source directories, CMake targets, and ownership.

  • Application lifecycle describes actual startup, frame processing, and shutdown.

  • Component system explains composition, registration, and reflection.

  • Resources and File I/O describe asset and scene persistence.

  • Input, Memory, and Threading describe current contracts.

  • CMake infrastructure records options, code generation, and checks.

  • UE5 comparison separates useful design patterns from proposed work.

The architecture and migration review summarizes decisions.

Design direction

The eight layers use focused libraries, JRM reflection, and component trees. Build dependencies and object ownership are separate graphs; see Gameplay and Application Lifecycle for their runtime use.

The current application links Editor and shares one scene between editor and game rendering. UE-style class names describe intended roles; they do not establish UE-equivalent behavior.
