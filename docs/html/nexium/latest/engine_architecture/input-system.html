Input System

Input flows one way. Platform turns every GLFW callback into a small typed event, NX::InputSystem collects the events into a per-frame queue, and once per frame it routes them to every registered InputController. A controller turns raw events into named actions that gameplay and editor code query or subscribe to.

Layer Where Role

Typed events

Platform/Input/Events

Value types for keyboard, mouse, gamepad, and window changes.

Window delegates

Platform::Window

One delegate per event kind, fired from the GLFW callback.

Gamepad polling

Platform::Joystick

Polled once per frame; reports changes as events.

Event queue and routing

NX::InputSystem (NxWorld)

Queues events, then feeds them to controllers.

Actions and bindings

NX::InputController (NxWorld/Framework/Input)

Reflected ECS component that owns named actions.

New input code should add actions to an InputController. The polled InputAction managers and the NxSubsystems/Input module are gone; Platform::Keyboard and Platform::Mouse still answer "is this down right now" for the few places that poll.

Events

Every event derives from NX::InputEvent, which carries three things: an EventType, an InputDeviceType, and an InputDeviceId. The base is deliberately non-polymorphic — its destructor and copy operations are protected, so an event can be neither destroyed nor copied through a base reference. Events are plain values.

The shared vocabulary lives in Events/InputEvent.h:

  • InputState is None, Pressed, Released, or Repeated. It is platform-independent: backends convert their native values explicitly, and None is distinct from Released.

  • InputModifier is a bitmask of Shift, Control, Alt, Super, CapsLock, and NumLock, with | and & operators.

  • InputButton wraps a 16-bit index — a keyboard key code, a mouse button, or a gamepad button, depending on the event that carries it. A default-constructed button is invalid (isValid() is false).

  • InputDeviceId identifies the device. 0 is InvalidInputDeviceId; keyboard and mouse events currently leave it at 0, and gamepads use the GLFW joystick index plus one.

AnyInputEvent is a std::variant over all event types, and it is what the queue stores:

using AnyInputEvent
    = std::variant<KeyboardEvent, TextInputEvent, MouseMoveEvent, MouseButtonEvent,
                   MouseScrollEvent, MouseEnterEvent, GamepadButtonEvent, GamepadAxisEvent,
                   GamepadConnectionEvent, WindowResizeEvent, WindowFocusEvent,
                   WindowIconifyEvent, WindowCloseEvent>;

/// Events are copied into the per-frame queue; keep them small and trivially copyable.
static_assert(sizeof(AnyInputEvent) <= 32, "Input events must stay small");
static_assert(std::is_trivially_copyable_v<AnyInputEvent>,
              "Input events must be trivially copyable");

The two assertions are the contract for adding an event: it must keep the variant within 32 bytes and trivially copyable. The InputEventType concept is satisfied by exactly the variant’s alternatives, and InputSystem declares one handle() overload per alternative, so a new event type fails to compile until it is handled. An overload may be empty: events that no controller source maps to are queued and then dropped.

Platform layer

Platform::Window installs the GLFW callbacks, builds the matching event, and triggers a delegate. GLFW constants do not leave Platform: Platform::ToInputState() and Platform::ToInputModifiers() in Platform/Input/Glfw.h convert actions and modifier bits, and an unknown action maps to InputState::None.

Delegates fire synchronously inside the GLFW callback, during Window::pollEvent(). A subscriber therefore sees an event before the queue is processed.

Window also keeps its own state from these events: isFocused(), isIconified(), and the global drag-and-drop tracker gDragDrop, which starts on a button press at the event’s position and becomes a drag after the cursor moves 15 pixels.

Click position

MouseButtonEvent::getPosition() is the cursor position sampled in the button callback. Use it rather than the current cursor position: by the time a queued click is handled the mouse may have moved.

Cursor delta

MouseMoveEvent::getDelta() comes from a CursorDeltaTracker owned by the window, not from static state. The first sample after a reset has a zero delta, which removes the jump that would otherwise follow a discontinuity:

Trigger Effect

Focus gained or lost

Tracker reset; next move reports zero delta.

Cursor enters or leaves the window

Tracker reset.

Window::setCursorMode()

Tracker reset.

Window::setCursorPosition()

Tracker re-based to the new position, so the warp is not reported as movement.

 
TEST(CursorDeltaTrackerTests, ResetDropsTheJumpAfterCursorModeChange)
{
    Platform::CursorDeltaTracker tracker;
    (void)tracker.update({ 10.f, 10.f });
    tracker.reset();
    EXPECT_EQ(tracker.update({ 900.f, 600.f }), glm::vec2(0.f));
    EXPECT_EQ(tracker.update({ 901.f, 600.f }), glm::vec2(1.f, 0.f));
}

Gamepads

Platform::Joystick is a static class polled once per frame, right after the window events. It supports only devices GLFW recognizes as standard gamepads; any other joystick is treated as disconnected. Its events go out through the window’s joystick delegates, with InputDeviceId set to the GLFW joystick index plus one.

  • Connection. A newly seen gamepad has its state reset and then reports GamepadConnectionEvent(connected = true).

  • Buttons. A GamepadButtonEvent is sent only when a button changes: Pressed or Released. There is no Repeated state for gamepad buttons.

  • Axes. A GamepadAxisEvent is sent when the value differs from the last reported value by more than the threshold (0.01 by default; setAxisChangeThreshold() clamps to [0, 2]). Comparing against the last reported value means slow drift still produces an event once it accumulates.

  • Rest values. Sticks rest at 0, triggers at -1 (getAxisRestValue()).

  • Disconnection. Before reporting connected = false, the class releases every button that was held and returns every axis that is off its rest value. A consumer never keeps a stuck button or axis from a device that went away.

isConnected(), isButtonPressed(), and getAxis() expose the current state for polling. Joystick::GamepadButton and Joystick::GamepadAxis name the standard layout.

InputSystem: queue and routing

GetInputSystem() is a Core::Singleton. GameInstance::initialize() calls initialize(window), which subscribes to the delegates marked Yes above and copies each event into the queue with queueEvent(). queueEvent() is public and constrained by InputEventType, so tests and tools can inject events without a window.

Each frame Runtime gathers events and then processes the queue:

Platform::Window::pollEvent();
Platform::Joystick::poll();
GetInputSystem().processEvents();
void InputSystem::processEvents()
{
    // Handlers may queue new events; they go to _events and are processed next frame.
    _processing.clear();
    std::swap(_events, _processing);

    for (auto* controller : _controllers)
    {
        controller->beginInputFrame();
    }

    for (const auto& event : _processing)
    {
        std::visit([this](const auto& concreteEvent) { handle(concreteEvent); }, event);
    }

    for (auto* controller : _controllers)
    {
        controller->endInputFrame();
    }

    // A callback may add or destroy controllers, including ones not visited yet. Walk a
    // snapshot so removing an entry cannot shift a neighbour out of the loop (its one-frame
    // triggers would be lost), and skip controllers that were destroyed meanwhile.
    // Controllers added by a callback are not in the snapshot and start with the next frame.
    _dispatching = _controllers;
    for (auto* controller : _dispatching)
    {
        if (isRegistered(controller))
        {
            controller->dispatchTriggeredCallbacks();
        }
    }
    _dispatching.clear();

    _processing.clear();
}

A frame therefore has four phases, and every controller finishes one phase before any controller starts the next:

  1. Begin. Each controller clears its per-frame state: press/release edges and the accumulated mouse delta and scroll.

  2. Route. Each queued event goes to every controller, in arrival order.

  3. End. Each controller combines its bindings into action values.

  4. Callbacks. Each enabled controller runs the callbacks of the actions triggered this frame.

Callbacks run last and outside the routing loops, so a callback may add or remove actions, or destroy controllers — including its own. They run over a snapshot of the registered controllers: a controller destroyed by an earlier callback is skipped, every other controller still runs its callbacks, and a controller initialized by a callback starts with the next frame.

The contract of the queue:

  • Events are stored by value in arrival order, across device types.

  • Two buffers are swapped each frame, so both keep their capacity and a steady-state frame does not allocate.

  • An event queued while the queue is being processed lands in the next frame.

  • Losing window focus does not drop queued events. GLFW synthesizes key releases after the focus callback, and they are queued after the presses they belong to.

  • resetInput() discards everything pending. It does not reset controllers.

TEST_F(InputSystemQueueTests, QueuedEventsKeepArrivalOrder)
{
    auto& window = Platform::GetWindow();

    NX::KeyboardEvent key;
    key.setState(NX::InputState::Pressed);
    window.onKeyPressed->trigger(key);

    NX::MouseMoveEvent move;
    move.setDelta({ 1.f, 2.f });
    window.onMouseMove->trigger(move);

    NX::GamepadButtonEvent gamepadButton(1);
    gamepadButton.setState(NX::InputState::Released);
    window.onJoystickButtonPressed->trigger(gamepadButton);

    const auto& events = NX::GetInputSystem().getPendingEvents();
    ASSERT_EQ(events.size(), 3U);
    EXPECT_TRUE(std::holds_alternative<NX::KeyboardEvent>(events[0]));
    EXPECT_TRUE(std::holds_alternative<NX::MouseMoveEvent>(events[1]));
    ASSERT_TRUE(std::holds_alternative<NX::GamepadButtonEvent>(events[2]));
    EXPECT_EQ(std::get<NX::GamepadButtonEvent>(events[2]).getDeviceId(), 1U);
    EXPECT_EQ(std::get<NX::MouseMoveEvent>(events[1]).getDelta(), glm::vec2(1.f, 2.f));
}

InputSystem holds non-owning controller pointers. A controller registers in onInitialize() and unregisters in onDeinitialize() and in its destructor. There is no priority between controllers and no event consumption: every controller sees every event. Routing is not filtered by focus or by a context either — see Enabling and gating.

InputController: actions and bindings

InputController is a reflected BaseComponent (ECS_DECL), so it can be attached to any scene object and its actions are saved with the component tree. It owns a list of InputAction values; an action is a name (Core::StringAtom) and a list of InputBinding values. Names are unique within a controller: addAction() returns false for an empty or duplicate name.

Bindings

A binding names one physical input and how to read it. All of these fields are reflected:

Field Meaning

source

Key, MouseButton, MouseDelta, MouseScroll, GamepadButton, or GamepadAxis.

code

Key, button, or axis code. Ignored for MouseDelta and MouseScroll.

trigger

For buttons: Down (on while held), Pressed (on for the frame of the press), or Released (on for the frame of the release).

shift, control, alt, super

Modifiers the binding requires.

modifierMatch

AtLeast: required modifiers must be held, extra ones are fine. Exact: exactly the required modifiers.

negate, swizzleYX

Value modifiers: flip the sign, then swap X and Y.

deadzone

Gamepad axes only: a normalized value with a smaller magnitude counts as zero. 0 (the default, and the value for data saved before the field existed) keeps every value.

Build bindings with the factories and chain the copies they return, rather than setting fields by hand:

Call Result

InputBinding::Key(key)

Key, Down, AtLeast.

InputBinding::Shortcut(key, modifiers)

Key, Pressed, Exact — an editor-style shortcut.

InputBinding::MouseButton(button)

Mouse button, Down.

InputBinding::MouseDelta(), InputBinding::MouseScroll()

Per-frame mouse vector.

InputBinding::GamepadButton(button), InputBinding::GamepadAxis(axis)

Gamepad button or axis.

withShift(), withControl(), withAlt(), withSuper(), withExactModifiers()

Add a required modifier, or switch to Exact.

onDown(), onPressed(), onReleased()

Change the trigger.

negated(), swizzled()

Set a value modifier.

withDeadzone(value)

Set the axis deadzone.

Modifiers follow two rules. Caps Lock and Num Lock are never compared. And modifiers are checked only on the press: a Down binding that is already held stays held when a modifier changes, and its release is always accepted.

The two match policies exist for different jobs. AtLeast suits gameplay — W keeps moving forward while Shift is held to sprint. Exact suits shortcuts — Ctrl+S does not fire on Ctrl+Shift+S. A binding has no notion of left versus right modifier keys: it compares the modifier mask the event carries.

toString() renders a binding for UI, such as Ctrl+Shift+S, Mouse Left, or Gamepad LeftX; the editor’s settings window lists every action this way.

Action values

Every binding contributes a glm::vec2, and the action’s value is the sum:

  • A button contributes (1, 0) while it is on, per its trigger.

  • MouseDelta and MouseScroll contribute the sum of that frame’s events, then reset.

  • GamepadAxis contributes (value, 0) and keeps the last value until the axis moves again. Triggers are normalized from their rest position, so they read 0 to 1 instead of -1 to 1.

negate and swizzleYX are applied to each contribution before summing. That is how several one-dimensional inputs become one 2D action — opposing keys cancel out, and a swizzled binding feeds the Y axis:

void Spectator2D::setupInputActions(InputController& input)
{
    using Axis = Platform::Joystick::GamepadAxis;
    using Key = Platform::Keyboard::Key;

    input.addAction("Pan"_atom, { InputBinding::MouseButton(Platform::Mouse::Key::Middle) });
    input.addAction("PointerDelta"_atom, { InputBinding::MouseDelta() });
    input.addAction("Scroll"_atom, { InputBinding::MouseScroll() });
    input.addAction("Boost"_atom, { InputBinding::Key(Key::Left_Shift),
                                    InputBinding::GamepadButton(
                                        Platform::Joystick::GamepadButton::LeftBumper) });
    input.addAction("Zoom"_atom, { InputBinding::Key(Key::Left_Control) });
    input.addAction("Move"_atom,
                    { InputBinding::GamepadAxis(Axis::LeftX),
                      InputBinding::GamepadAxis(Axis::LeftY).negated().swizzled() });
    input.addAction("GamepadZoom"_atom,
                    { InputBinding::GamepadAxis(Axis::RightTrigger),
                      InputBinding::GamepadAxis(Axis::LeftTrigger).negated() });
}

A binding’s deadzone is a per-axis threshold applied after normalization, so a trigger is compared on its 0 to 1 range. It is not a rescale: a value outside the deadzone passes through unchanged, and a value inside it is zero, so stick drift neither activates the action nor triggers its callbacks. A consumer that needs a radial deadzone on the whole stick vector still applies its own, as the spectators do.

Reading actions

Call Returns

isActive(name)

Whether the action’s value is non-zero this frame.

wasTriggered(name)

Whether the action started this frame: it became active, a Down binding was pressed, or a Pressed/Released binding fired.

getValue<bool>(name)

Same as non-zero value.

getValue<float>(name)

The X component.

getValue<glm::vec2>(name)

The full value.

 
TEST_F(InputControllerRuntimeTests, DownBindingIsActiveWhileHeld)
{
    addAction("Fire", { KeyBinding(Key::Space, NX::InputTrigger::Down) });
    controller->initialize();

    key(Key::Space, NX::InputState::Pressed);
    frame();
    EXPECT_TRUE(controller->isActive("Fire"_atom));
    EXPECT_TRUE(controller->wasTriggered("Fire"_atom));

    frame();
    EXPECT_TRUE(controller->isActive("Fire"_atom));
    EXPECT_FALSE(controller->wasTriggered("Fire"_atom));

    key(Key::Space, NX::InputState::Released);
    frame();
    EXPECT_FALSE(controller->isActive("Fire"_atom));
}

A press and release that both arrive within one frame still count: wasTriggered() is true for that frame even though isActive() is not.

Asking for an action the controller does not have returns the default (false or zero) and logs one warning per name.

Callbacks

onTriggered(name, callback) registers a void() callback that runs once in every frame where wasTriggered(name) is true; addAction() has an overload that takes the callback directly. A callback can be registered before its action exists. clearCallbacks(name) removes them. Callbacks are runtime-only and are not saved with the component.

TEST_F(InputControllerRuntimeTests, TriggeredCallbackRunsOncePerPress)
{
    int calls = 0;
    ASSERT_TRUE(controller->addAction("Fire"_atom, { NX::InputBinding::Key(Key::Space) },
                                      [&] { ++calls; }));
    controller->initialize();

    key(Key::Space, NX::InputState::Pressed);
    frame();
    EXPECT_EQ(calls, 1);

    frame();
    EXPECT_EQ(calls, 1);

    key(Key::Space, NX::InputState::Released);
    key(Key::Space, NX::InputState::Pressed);
    frame();
    EXPECT_EQ(calls, 2);
}

Persistence

_actions is a FIELD(), and InputBinding and InputAction are reflected types with JSON adapters, so a controller round-trips through JRM with its component. Runtime state — held buttons, values, callbacks — is not reflected and is never saved. Code that builds its actions in onInitialize() should first look for an existing child controller, as the spectators do, so a deserialized controller is reused instead of duplicated.

Enabling and gating

InputSystem routes every event to every registered controller, so the owner decides when its controller counts. The switch is the component’s enabled state:

  • A disabled controller returns defaults from isActive(), wasTriggered(), and getValue(), and its callbacks do not run.

  • It still receives events. A key released while the controller is disabled is recorded, so nothing is stuck when it is enabled again.

  • onDeinitialize() unregisters the controller and clears all held state.

Owner Rule

GameEditor

Enabled unless ImGui wants text input, so shortcuts do not fire while typing.

NxECSBasedEditor

Enabled only while its window is focused and ImGui does not want text input.

Spectators

Enabled only while their scene is the active one.

Finer conditions stay in the consumer: the spectators ignore scroll and gamepad input, and the editor ignores Delete, unless isApplicationViewportFocused(); the editor’s pick click requires the cursor over the viewport instead.

Still polling

game-example/Player has not been ported: it reads W/A/S/D and the arrow keys through Platform::Keyboard::IsKeyPressed().

Polled queries such as Platform::Mouse::GetPosition() and Platform::Keyboard::IsKeyPressed() remain for reading the current state at an arbitrary moment, for example the editor’s object picker. Reactions to a press, a release, or a value changing should be actions, so they are routed, gated, and testable.
