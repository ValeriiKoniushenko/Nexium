Application Lifecycle

game-example/main.cpp creates gGameInstance, then a Runtime and EditorIntegration. Runtime borrows the instance; the integration attaches editor hooks through ApplicationIntegration.

Startup

Runtime::run() initializes the instance, runs the frame loop, then saves state. GameInstance::initialize() performs these steps:

  1. Create the Platform window and subscribe to resize events.

  2. Scan assets, load shaders, and configure vertex attributes.

  3. Initialize the editor integration and build the component factory’s type/tag map.

  4. Initialize Scene and subscribe to object additions for camera discovery.

  5. Read editor, window, scene, and World state; call onInitializeReadCache().

  6. Generate the default and example animation atlases; call onLoadCoreResources().

Initialization still uses global accessors. Binding Runtime to an instance does not provide independent concurrent game instances.

Each frame

Window events are polled first. Updates use the previous frame’s measured delta; the first delta is zero.

Operation GameOnly Editor

Every frame.

Keyboard shortcuts, if attached.

GameInstance tick

After Scene drawing, if a camera exists.

After Scene drawing, if a camera exists.

Scene ticking does not require a camera; GameInstance::onTick and scene drawing do. After updates, the loop throttles unfocused/iconified windows, checks --timeout, swaps buffers, and records elapsed time in World. Rendering and throttling contribute to that time.

Modes and shutdown

Editor mode requires both the Editor render mode and an attached integration. F1 switches rendering paths, which share the same gameScene. There is no isolated Play/Stop session or paused simulation clock; gameplay edits can be saved at shutdown.

After a normal loop exit, saveAllToCache() writes editor state, World, Scene, and Window, then calls onSaveAll(). Exceptions escaping initialization or the loop bypass this save call.

The example destroys EditorIntegration before Runtime and resets gGameInstance last. Keep that order because both objects borrow their dependencies. See File I/O for persistence and Ownership for lifetimes.

Implementation: NxRuntime/Runtime.cpp, NxWorld/Framework/GameInstance.cpp, and Editor/EditorIntegration.cpp.
